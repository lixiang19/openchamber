## 关键问题
1. 默认模板实例应写到哪里，才能既可见又不污染配置目录？
2. 首次启动自动创建与手动“模板创建项目”如何共用一套模板复制逻辑？
3. 新增项目入口如何在桌面端与浏览器端保持一致？

## 已做决策
| Decision | Rationale |
|----------|-----------|
| 默认项目实例写入 `~/OpenAurora/OpenAurora Home` | 对用户可见，符合“真实项目目录”语义，不与 `~/.config/openaurora` 配置数据混淆 |
| 模板源放在 `packages/web/server/project-template/openaurora-home/` | 跟随应用打包，服务端可直接复制，发布一致 |
| 首次启动 bootstrap 挂在 `/api/config/settings` 读取链路 | 前端在 `main.tsx` 渲染前会先同步 settings，能保证左侧项目列表首屏即有默认项目 |
| 新增项目改成统一创建对话框 | 同时覆盖导航栏、项目设置页、移动端和空项目首屏入口，避免重复逻辑 |
| 模板创建允许自动创建缺失的父目录 | 默认路径 `~/OpenAurora` 初次往往不存在，用户手填新父目录时也应可直接创建 |

## 注意事项
- 启动自动创建只应执行一次，不能在用户后来清空项目后反复强制创建
- 模板创建不做覆盖式兜底，目标目录已存在且非空时直接报错
- UI 颜色继续使用主题 token，不写硬编码颜色
