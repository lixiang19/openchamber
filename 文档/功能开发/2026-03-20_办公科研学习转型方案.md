# 办公科研学习转型 方案

- 状态：已确认
- 日期：2026-03-20
- Owner：OpenCode
- 目标版本/里程碑：信息架构第一轮

## 1. 背景与问题

- 背景：当前产品底层能力很强，但默认心智仍然偏代码助手，和办公、科研、学习场景不完全匹配。
- 现象/痛点：界面虽然大量使用英文，但用户可见文案里仍然直接暴露 `session`、`git`、`terminal`、`diff` 等开发语义；`PlanView` 入口过深且受条件隐藏，普通用户几乎感知不到；任务系统已存在，不适合继续做重型项目管理。
- 成功定义：在不破坏现有核心能力的前提下，把默认体验调整为“工作台 + 文档/资料 + 对话”结构，让非编程用户第一次打开就知道这不是只给写代码的人用的。

## 2. 目标与非目标

- 目标：
  - 将默认 IA 从 code-first 调整为办公/科研/学习友好的工作台结构。
  - 弱化 `session/git/terminal/diff` 的直接暴露，强化首页、文档入口、资料入口。
  - 保持任务系统轻量，只做表达和布局优化，不引入复杂流程引擎。
  - 继续增强 `FilesView`，让它更像资料库而不是代码文件树。
- 非目标：
  - 不在这一轮重写所有底层状态模型。
  - 不在这一轮删除开发者能力；只调整默认暴露层级。
  - 不在这一轮把 Todo 做成复杂项目管理系统。

## 3. 现状探索（Explorer）

- 入口与调用链：
  - `packages/ui/src/stores/useUIStore.ts:8` - 当前主工作区仍然是 `chat | plan | git | diff | terminal | files`。
  - `packages/ui/src/components/layout/Header.tsx:555` - `PlanView` 显示由 `planTabAvailable` 控制，不是稳定主入口。
  - `packages/ui/src/components/layout/Header.tsx:611` - 计划文件不存在时，Plan 会被自动隐藏并切回 Chat。
  - `packages/ui/src/components/layout/ContextPanel.tsx:415` - `PlanView` 现在主要在 context panel 中渲染，不是首页级内容区。
  - `packages/ui/src/components/mobile/MobileChatShell.tsx:196` - 移动端只在 overflow menu 里能看到 Plan，存在感很弱。
  - `packages/ui/src/components/views/InboxView.tsx:467` - 首页空状态仍然以 `sessions` 为中心。
- 关键数据结构/状态：
  - `packages/ui/src/stores/useUIStore.ts:9` - 顶层页面只有 `workspace | inbox`，适合把 `inbox` 重塑为工作台首页。
  - `packages/ui/src/stores/useUIStore.ts:10` - 右侧栏仍然是 `git | files | todo`，明显是开发工作区结构。
  - `packages/ui/src/components/session/sidebar/SidebarHeader.tsx:365` - 搜索按钮、placeholder 仍直接使用 `Search sessions` 文案。
  - `packages/ui/src/components/session/SessionSidebar.tsx:389` - 空状态文案仍是 `No sessions yet / start coding`。
- 约束与坑点：
  - `PlanView` 依赖 plan 文件存在性，直接把它当稳定导航会造成用户“时有时无”的感知问题。
  - 任务系统已经有工程化基础，但继续叠加复杂字段和流程会偏离你的要求。
  - `Git` / `Terminal` / `Diff` 不能粗暴删除，因为现有用户与底层流程还依赖这些能力。

## 4. 资料与依据（Librarian）

- 关键结论：
  - 首页最适合采用“主 CTA + 最近活动 + 快捷入口”的轻量工作台结构，而不是继续强化会话收件箱。
  - 高级能力如 Terminal/Git 更适合按角色或场景渐进披露，默认隐藏、需要时出现，比硬删除更稳妥。
  - 对办公/科研/学习场景，最自然的核心关系应是“对话驱动 -> 文档沉淀 -> 资料引用”，而不是“会话 -> 代码 -> Git”。

## 5. 方案概览（主方案）

### 5.1 方案摘要

- 一句话：以最小侵入方式重构默认信息架构：把 `Inbox` 升级为首页工作台，把 `PlanView` 重命名并前置为文档入口，把 `FilesView` 强化为资料库，把开发者能力下沉到高级层。
- 取舍：不动底层核心引擎和大部分 store，只优先改用户看见的术语、导航、首页、入口层级。
- 影响面：`InboxView`、`Header`、`RightSidebarTabs`、`PlanView` 入口、`SessionSidebar` 文案、`FilesView` 功能定义与默认模板内容。

### 5.2 风险与回滚

- 风险：
  - 术语替换过快会让老用户不适应：通过“开发者模式”或兼容文案缓冲。
  - `PlanView` 入口前置后仍受 plan 文件条件限制：第一轮先改命名和入口策略，再决定是否脱离 plan 文件模型。
  - 首页改动过大可能影响既有快捷操作：保留最近对话与新建对话主路径。
- 回滚：
  - 首页工作台可作为 `inbox` 新实现保留开关；若效果不佳可切回旧版 Inbox。
  - 导航与文案改造以 UI 层为主，不改底层数据结构，回滚成本低。

## 6. 详细设计（Spec）

### 6.1 交互/行为（如适用）

- 用户流程：
  - 打开应用先进入“工作台首页”，看到主输入区、最近对话、最近文档、最近资料。
  - 进入工作区后，左侧不再强调 `sessions`，而强调“对话历史/线程/任务历史”。
  - 文档入口稳定可见，不再依赖用户先理解 `Plan` 这个术语。
  - 资料入口继续强化 `FilesView`，支持更好的 PDF/文档/资料浏览与提炼。
- 边界条件：
  - 若当前没有 plan 文件，文档入口也应有可解释的空态，而不是彻底消失。
  - 若用户开启开发者模式，`Git`、`Terminal`、`Diff` 可以继续出现。
  - Todo 保持轻量：不增加复杂状态机、负责人、流程审批等字段。

### 6.2 接口与契约

- API/函数签名：
  - 不要求第一轮新增后端 API，优先使用现有设置与 UI store 完成重构。
  - 可选新增：`developerMode` 或 `advancedToolsVisible` 设置项，用于控制高级功能显示层级。
- 错误码/异常：
  - 本轮以 UI 层改造为主，无新增关键错误协议。

### 6.3 数据与存储（如适用）

- Schema/字段：
  - `developerMode`：`boolean`（控制 `git/terminal/diff` 等默认显示）
  - `homeDashboardLayout`：`string`（可选，控制首页卡片布局）
- 迁移策略：
  - 默认对老用户保持兼容：若已有使用开发能力的痕迹，可自动保守显示高级入口。
  - 文案替换不需要数据迁移。

### 6.4 兼容性与发布

- 兼容策略：
  - 第一阶段只改文案、导航权重和首页结构，不删任何底层能力。
  - 保留旧术语兼容一段时间，例如内部状态仍叫 `session`，UI 上逐步改成 `history/thread/task`。
- 发布步骤：
  - 先发布首页 + 文案 + 文档入口调整。
  - 再发布右侧栏与高级能力显隐策略。
  - 最后再增强 FilesView 的资料能力。

### 6.5 可观测性

- 日志：
  - 记录首页卡片点击率、文档入口点击率、FilesView 打开率、高级能力开启率。
- 指标：
  - 首页进入后首次操作分布。
  - `Plan`/文档入口曝光率与使用率。
  - `Git/Terminal` 的默认隐藏后使用下降或投诉情况。
- 告警：
  - 若首页改造后新建对话率明显下降，应回看 CTA 布局。

## 7. 验收标准（必须可验证）

- 功能验收：
  - [ ] 首页从“会话收件箱”改成“工作台首页”，且保留最近活动与新建对话主入口。
  - [ ] UI 上直接暴露的 `session` 文案完成首轮替换，不再作为主要用户术语。
  - [ ] `PlanView` 有稳定、可发现的入口与空态说明，不再是“看不到就像不存在”。
  - [ ] `FilesView` 定位升级为资料库增强入口，并明确作为下一阶段重点。
  - [ ] Todo 不增加复杂流程，只做轻量整理与表达优化。
- 非功能验收：
  - [ ] 性能：首页改造后首屏无明显额外阻塞。
  - [ ] 可靠性：未破坏现有 Chat、Files、Git、Terminal 主路径。
  - [ ] 安全：不引入额外权限面或隐式后台执行。
