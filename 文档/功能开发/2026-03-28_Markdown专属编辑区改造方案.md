# Markdown专属编辑区改造方案

- 状态：已确认
- 日期：2026-03-28
- Owner：Codex
- 目标版本/里程碑：FilesView Markdown 编辑体验切换

## 1. 背景与问题

- 背景：当前项目文件区对 Markdown 文件仍采用“预览/编辑”双态，预览依赖 `react-markdown` 渲染，编辑则回退到通用 `CodeMirrorEditor`，体验上仍是普通文本编辑而不是专属 Markdown 编辑区。
- 现象/痛点：Markdown 文件在项目文件区没有独立编辑语义，预览和编辑分支分裂，状态管理重复，主视图与全屏视图都各自维护一套 Markdown 分支，后续继续增强会越来越难。
- 成功定义：在不改变现有文件树、标签、保存、全屏和上下文布局的前提下，把项目内 `.md/.markdown` 文件统一切到 Milkdown 专属编辑区，移除 FilesView 中现有 Markdown 预览分支。

## 2. 目标与非目标

- 目标：
  - 把 `FilesView` 中项目 Markdown 文件的内容区切换为 Milkdown 专属编辑区。
  - 保留现有文件树、顶部/浮动控制、自动保存、脏状态保护、全屏入口与外层布局。
  - 让 Markdown 编辑沿用现有 `draftContent -> saveDraft -> files.writeFile` 主链路，不重做整套文件保存架构。
  - 在主视图和全屏视图中统一复用同一个 Markdown 编辑组件，消除双份预览逻辑。
  - 补齐常见 Markdown 能力，至少覆盖 CommonMark + GFM 级别的表格、任务列表、删除线等基础语义。
- 非目标：
  - 不改聊天区、工具输出区、更新弹窗等其他 `SimpleMarkdownRenderer` 使用场景。
  - 不在本次内重做 `PlanView` 的只读 Markdown 预览逻辑。
  - 不引入“预览/编辑”双态并存的新过渡方案，Markdown 文件只保留专属编辑区。
  - 不在本次内做独立发布开关或兼容旧 Opencode 逻辑。

- 入口与调用链：
  - `packages/ui/src/components/views/FilesView.tsx:261` - `isMarkdownFile` 负责识别 `.md/.markdown`。
  - `packages/ui/src/components/views/FilesView.tsx:496` - `mdViewMode` 维护 Markdown 预览/编辑双态。
  - `packages/ui/src/components/views/FilesView.tsx:1129` - `saveDraft` 通过 `files.writeFile` 落盘，是当前文件编辑保存入口。
  - `packages/ui/src/components/views/FilesView.tsx:1647` - `isMarkdown` 决定 Markdown 分支是否生效。
  - `packages/ui/src/components/views/FilesView.tsx:2153` - `renderFloatingFileControls` 在 Markdown 文件上挂接预览切换按钮。
  - `packages/ui/src/components/views/FilesView.tsx:2570` - 主视图在 Markdown 预览态渲染 `SimpleMarkdownRenderer`。
  - `packages/ui/src/components/views/FilesView.tsx:2849` - 全屏视图再次复制同样的 Markdown 预览分支。
- 关键数据结构/状态：
  - `packages/ui/src/components/views/FilesView.tsx:578` - `draftContent` / `fileContent` 是当前文件文本链路的核心状态。
  - `packages/ui/src/components/views/FilesView.tsx:1127` - `isDirty` 通过 `draftContent !== displayedContent` 判定未保存修改。
  - `packages/ui/src/components/ui/CodeMirrorEditor.tsx:50` - 通用编辑器支持 `value`、`onChange`、`readOnly`、搜索和视图 ready 生命周期。
  - `packages/ui/src/components/views/PreviewToggleButton.tsx:21` - 预览按钮仅负责切换模式，不参与保存链路。
- 约束与坑点：
  - Markdown 现在不是单一编辑器，而是预览与通用文本编辑器之间的条件分支，替换时必须同时处理主视图与全屏视图。
  - `draftContent` 已经承载自动保存、关闭确认、切文件保护、复制内容等行为，不能让 Milkdown 绕开这条主链路。
  - 若 Milkdown 在初始化时对 Markdown 做序列化归一化，可能造成“未编辑却变脏”的假差异，需要显式治理。
  - 当前仓库说明文案仍写着“markdown preview”，执行时需要同步更新相关描述。

## 4. 资料与依据（Librarian）

- 关键结论：
  - Milkdown 在 React 项目中的稳妥接入应基于官方 React SDK 组合，而不是直接把默认演示 UI 整块塞进现有界面；最低需要 `@milkdown/core`、`@milkdown/react`、基础 preset，实际落地建议补 `@milkdown/plugin-listener` 与 GFM preset。
  - 外部字符串状态不能做成每次 render 都强制覆盖编辑器内容的“完全受控组件”，否则会破坏光标、撤销栈和长文档性能；正确做法是“文档切换时显式注入，编辑过程中监听回写”。
  - 工具栏和主题应由 Ridge 现有 UI 壳层接管，Milkdown 只负责 Markdown 文档模型与编辑能力；否则默认主题会破坏现有文件区视觉语言。
  - 现有环境无法直接抓取用户给出的官方文档页面，但以上方案遵循 Milkdown 官方 Getting Started 的常规接入模型；执行前会再按包名和 API 做一次对照核验。

## 5. 方案概览（主方案）

### 5.1 方案摘要

- 一句话：在 `FilesView` 中新增一个基于 Milkdown 官方 React SDK 的 `MarkdownMilkdownEditor`，让 Markdown 文件始终走专属编辑区，并继续把 `draftContent` 作为文件系统保存链路的唯一文本入口。
- 取舍：不采用 `@milkdown/crepe` 的默认整套皮肤与 UI，而是使用官方底层 React 接入加自定义壳层，这样可以保留现有 Ridge 文件区界面，不把视觉和交互交给第三方默认样式。
- 影响面：`packages/ui/src/components/views/FilesView.tsx`、新的 Markdown 编辑组件、浮动工具区按钮、依赖清单、README/相关文案会变化；非 Markdown 文件浏览与聊天 Markdown 渲染不受影响。

### 5.2 风险与回滚

- 风险：
  - 编辑器初始化后输出的 Markdown 被规范化，导致文件刚打开就进入 dirty 状态：通过“仅在用户编辑后回写 draft”与“文档切换时显式同步”规避。
  - Milkdown 样式泄漏污染现有页面：通过独立组件作用域和主题 token 映射隔离。
  - 主视图与全屏视图若各自创建独立实例，可能出现行为不一致：通过抽出统一组件并在两处复用解决。
  - Markdown 搜索、换行、复制等现有控制与 Milkdown 能力不完全一致：本次保留保存/复制/路径/全屏等核心控制，逐项确认哪些按钮应保留、重命名或删除。
- 回滚：
  - 回滚不做运行时开关，直接以 Git 版本回退到本次变更前的 `FilesView` 结构。

## 6. 详细设计（Spec）

### 6.1 交互/行为（如适用）

- 用户流程：
  1. 用户在文件树中选择 `.md/.markdown` 文件。
  2. `FilesView` 读取文件后仍把原始文本写入 `fileContent` 与 `draftContent`。
  3. 内容区直接挂载 `MarkdownMilkdownEditor`，不再出现 `SimpleMarkdownRenderer` 预览态。
  4. 用户在 Milkdown 中编辑时，组件通过 listener 把最新 Markdown 文本回写 `setDraftContent`。
  5. 现有自动保存、手动保存、切文件脏状态拦截继续基于 `draftContent` 生效。
  6. 用户进入全屏时，仍看到同一个 Markdown 编辑区能力，而不是另一套预览实现。
- 边界条件：
  - 大文件仍沿用现有文件读取限制；若超出当前可编辑字符上限，Markdown 文件不再进入专属编辑区。
  - 图片/SVG/普通文本保留现有分支，不受此次改造影响。
  - 若 Milkdown 初始化失败，直接显示错误态，不回退到旧 preview 分支。

### 6.2 接口与契约

- API/函数签名：
  - `MarkdownMilkdownEditor`: `{ documentKey: string; value: string; onChange: (markdown: string) => void; readOnly?: boolean; className?: string; onReady?: (...) => void }`
  - `FilesView` 对 Markdown 文件分支：`selectedFile.path + draftContent + setDraftContent -> MarkdownMilkdownEditor`
  - `saveDraft`: `selectedFile.path + draftContent -> files.writeFile(path, content)`，保持现有契约不变。
- 错误码/异常：
  - Milkdown 初始化失败时只在 UI 层报告错误，不在文件系统层兜底为旧预览。
  - 文件写入失败继续沿用现有 toast 错误提示。

### 6.3 数据与存储（如适用）

- Schema/字段：
  - `draftContent: string`：文件编辑中的唯一待保存文本。
  - `fileContent: string`：最近一次成功加载/保存后的基准文本。
  - `selectedFile.path: string`：文档切换键，用于驱动 Milkdown 仅在切文件时重建或重载。
- 迁移策略：
  - 不做数据迁移；只替换前端编辑器实现与 UI 分支。
  - 移除 `FilesView` 中 Markdown 专用 `mdViewMode` 的持久化读取/写入逻辑。

### 6.4 兼容性与发布

- 兼容策略：不保留旧的 Markdown preview/edit 双态，项目文件中的 Markdown 统一进入 Milkdown 编辑区。
- 发布步骤：
  1. 引入 Milkdown React 依赖与编辑组件。
  2. 切换 `FilesView` 主视图 Markdown 分支。
  3. 切换 `FilesView` 全屏 Markdown 分支。
  4. 删除预览切换状态、按钮与无用依赖/文案。
  5. 做最小手测后提交。

### 6.5 可观测性

- 日志：
  - 记录 Milkdown 初始化失败、文档切换重载失败、序列化回写异常。
- 指标：
  - 关注 Markdown 文件首次打开耗时、输入到 `draftContent` 回写延迟、保存成功率。
- 告警：
  - 暂不新增系统告警；以 UI 可见错误与开发期调试日志为主。

## 7. 验收标准（必须可验证）

- 功能验收：
  - [ ] 在 `FilesView` 中打开 `.md/.markdown` 文件时，主内容区直接显示 Milkdown 编辑器，而不是 `react-markdown` 预览。
  - [ ] 在全屏文件视图中打开同一 Markdown 文件时，仍显示同一套 Milkdown 编辑体验。
  - [ ] 编辑 Markdown 后，现有 dirty 状态、自动保存、手动保存和关闭确认行为保持可用。
  - [ ] 切换到非 Markdown 文件时，普通文本/图片/SVG 分支行为不回归。
  - [ ] `FilesView` 中不再保留 Markdown 专用 preview 按钮与 `mdViewMode` 状态。
- 非功能验收：
  - [ ] 性能：中等体量 Markdown 文件首次打开与输入响应无明显卡顿。
  - [ ] 可靠性：切换文件、全屏切换、保存后重新打开时不出现内容丢失或假 dirty。
  - [ ] 安全：最终写盘始终是纯 Markdown 文本，不经过 HTML 中转。
