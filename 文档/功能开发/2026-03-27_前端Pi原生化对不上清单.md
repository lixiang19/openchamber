## 1. 总体判断

当前前端已经有一条 Pi-native 状态链路：

- `packages/ui/src/lib/pi/client.ts:89` - 直接订阅 `/api/pi/events`
- `packages/ui/src/lib/pi/reducer.ts:496` - 处理 `pi_ui_event`
- `packages/ui/src/lib/pi/reducer.ts:554` - 处理 `pi_event`
- `packages/ui/src/lib/pi/types.ts:142` - `toolExecutions`
- `packages/ui/src/lib/pi/types.ts:143` - `interactiveRequests`
- `packages/ui/src/lib/pi/types.ts:144` - `statusEntries`
- `packages/ui/src/lib/pi/types.ts:145` - `widgets`

但 UI 层仍有大块区域停留在“旧 runtime 形状 / OpenCode 语义”中间层，因此出现“功能在、UI在、字段对不上”的状态。

## 5. 对齐原则

1. 不删任何现有 UI 组件与产品功能
2. 优先改字段和状态来源，不改视觉层级和入口位置

5. 不能因为 Pi 现阶段没有对齐 permission，就删除 Permission UI；必须在计划文档中作为独立对齐项保留
