## 功能概述

对话页面添加"精卫填海"按钮。启用后，当 AI 回复完成时自动检查任务是否完成。

**核心闭环**：启用 → 对话完成 → 自动发送检查提示 → AI 回复 → 检测完成标记 → 停止/继续

---

## 核心机制

### 1. 触发条件

```
sessionStatus: busy → idle
+ 本轮有新增的 assistant 消息（messageId ≠ lastAssistantMessageId）
+ 当前会话是活动会话
+ jingweiState.enabled = true
+ jingweiState.phase = 'idle'
+ 当前标签页是 owner（isOwner() 确认）
+ 输入框为空（debounce 到期时二次校验）
```

### 2. 检查提示

```
仅执行以下二选一：
1. 若文档要求仍有未完成项，继续严格依据文档开发，不得扩展范围。
2. 若已全部完成，仅回复：[JINGWEI_DONE]
不要输出其他确认语。
```

### 3. 终止条件

- AI 回复内容**完全等于** `[JINGWEI_DONE]`（逐字匹配，含大小写）
- 只检查自动提示后的**首条 assistant 消息**

```typescript
function checkCompletion(content: string): boolean {
  return content === '[JINGWEI_DONE]';  // 严格逐字匹配
}
```

## Owner机制（Best-Effort）

```typescript
// hooks/useJingweiOwner.ts

const TAB_ID = generateShortId();
const OWNER_KEY = 'jingwei_owner_';

/**
 * Best-effort owner：使用localStorage+回读，极大降低双发概率
 * 接受极小概率双发（用户体验降级，非正确性问题）
 */

// 尝试成为owner（写+回读确认）
export function claimOwner(sessionId: string): boolean {
  const key = OWNER_KEY + sessionId;
  const claim = { tabId: TAB_ID, time: Date.now() };
  
  localStorage.setItem(key, JSON.stringify(claim));
  
  // 回读确认
  const actual = localStorage.getItem(key);
  if (!actual) return false;
  
  const parsed = JSON.parse(actual);
  return parsed.tabId === claim.tabId && parsed.time === claim.time;
}

// 检查当前是否是owner（只读，不竞争）
export function isOwner(sessionId: string): boolean {
  const key = OWNER_KEY + sessionId;
  const current = localStorage.getItem(key);
  if (!current) return false;
  
  const { tabId, time } = JSON.parse(current);
  return tabId === TAB_ID && Date.now() - time < 15000;
}

export function releaseOwner(sessionId: string): void {
  const key = OWNER_KEY + sessionId;
  const current = localStorage.getItem(key);
  if (current && JSON.parse(current).tabId === TAB_ID) {
    localStorage.removeItem(key);
  }
}

// 心跳：每5秒刷新
export function heartbeat(sessionId: string): void {
  if (isOwner(sessionId)) {
    const key = OWNER_KEY + sessionId;
    const current = JSON.parse(localStorage.getItem(key) || '{}');
    localStorage.setItem(key, JSON.stringify({ 
      ...current, 
      time: Date.now() 
    }));
  }
}
```

## 状态迁移表

| 当前 phase | 事件 | 新 phase | 动作 |
|------------|------|----------|------|
| idle | 用户点击启用 | idle, enabled=true | toast 已启用 |
| completed/error | 用户点击启用 | idle, enabled=true, 重置所有追踪字段 | reset |
| any | 用户点击关闭 | idle, enabled=false | disable |
| idle | busy→idle + 新assistant + claimOwner成功 | idle, 启动 debounce | debounce 1.5秒 |
| debounce中 | 用户输入/发送/切会话/失owner | idle | 取消 debounce |
| debounce到期 | 校验通过 + isOwner确认 | sending | 发送（checkCount++, 重置sendRetryCount） |
| sending | 发送成功，获得messageId | waiting | awaitingSince=now, 保存lastPromptMessageId |
| sending | 失败，sendRetryCount < 1 | sending | sendRetryCount++, 重试 |
| sending | 失败，sendRetryCount >= 1 | error, blockReason='send_failed' | 停止 |
| waiting | 首条assistant + 完全匹配`[JINGWEI_DONE]` | completed | enabled=false, toast完成 |
| waiting | 首条assistant + 不匹配 | idle | 继续下一轮 |
| waiting | 超时5分钟 | idle, blockReason='reply_timeout' | 降级 |
| waiting | assistant失败/被停止 | idle | 重置 |
| any | checkCount >= 10 | error, blockReason='max_count_reached' | 停止 |
| waiting | 恢复后锚点丢失 | error, blockReason='anchor_lost' | 停止 |

**关键保证**：waiting 必须有出口（完成/超时/失败/丢失）

## 发送逻辑（完整链路，位于 hooks/useJingwei.ts）

```typescript
// hooks/useJingwei.ts 中的发送函数

async function sendCheckPrompt(
  sessionId: string,
  state: JingweiState
): Promise<{ success: boolean; messageId?: string }> {
  // 二次确认：必须是owner才能发送（只检查，不重新claim）
  if (!isOwner(sessionId)) {
    return { success: false };
  }
  
  try {
    const messageId = await messageStore.sendMessage({
      sessionId,
      content: JINGWEI_CHECK_PROMPT,
      metadata: { jingweiAutoPrompt: true }
    });
    
    return { success: true, messageId };
  } catch (error) {
    // 重试逻辑
    const retryCount = state.sendRetryCount || 0;
    if (retryCount < 1) {
      // 更新重试计数，递归重试
      updateJingweiState(sessionId, { sendRetryCount: retryCount + 1 });
      return sendCheckPrompt(sessionId, { ...state, sendRetryCount: retryCount + 1 });
    }
    return { success: false };
  }
}

// 调用方（useJingwei.ts）必须处理返回的 messageId
async function handleSend(sessionId: string, state: JingweiState) {
  const result = await sendCheckPrompt(sessionId, state);
  
  if (result.success && result.messageId) {
    // 关键：保存messageId到state，作为后续对账锚点
    updateJingweiState(sessionId, {
      phase: 'waiting',
      lastPromptMessageId: result.messageId,
      awaitingSince: Date.now(),
      sendRetryCount: 0
    });
  } else {
    updateJingweiState(sessionId, {
      phase: 'error',
      blockReason: 'send_failed'
    });
  }
}
```

## 恢复对账逻辑

```typescript
// lib/jingwei/reconcile.ts

export function reconcile(
  state: JingweiState,
  messages: Message[]
): JingweiState {
  if (state.phase !== 'waiting') return state;
  
  // 无锚点，无法对账，进入error
  if (!state.lastPromptMessageId) {
    return { 
      ...state, 
      phase: 'error', 
      blockReason: 'anchor_lost',
      awaitingSince: undefined 
    };
  }
  
  const anchorIndex = messages.findIndex(m => m.id === state.lastPromptMessageId);
  
  // 锚点丢失（可能被裁剪）
  if (anchorIndex === -1) {
    return { 
      ...state, 
      phase: 'error', 
      blockReason: 'anchor_lost',
      awaitingSince: undefined 
    };
  }
  
  // 查找锚点后的首条assistant
  const after = messages.slice(anchorIndex + 1);
  const firstAssistant = after.find(m => m.role === 'assistant');
  
  if (!firstAssistant) {
    // 检查超时
    if (state.awaitingSince && Date.now() - state.awaitingSince > 5 * 60 * 1000) {
      return { 
        ...state, 
        phase: 'idle', 
        blockReason: 'reply_timeout',
        awaitingSince: undefined 
      };
    }
    return state; // 继续等待
  }
  
  // 严格判定
  const completed = checkCompletion(firstAssistant.content);
  
  return {
    ...state,
    phase: completed ? 'completed' : 'idle',
    lastAssistantMessageId: firstAssistant.id,
    awaitingSince: undefined,
    enabled: completed ? false : state.enabled
  };
}

export function checkCompletion(content: string): boolean {
  return content === '[JINGWEI_DONE]';
}
```

## 关键契约（诚实明确）

### 1. Owner机制
```
能力边界：
  - best-effort，使用localStorage+回读，极大降低双发概率
  - 无法100%保证（浏览器无原子锁），接受极小概率双发

正确性保证：
  - 触发时：claimOwner() 竞争
  - 发送前：isOwner() 二次确认（只读检查，不重新竞争）
  - 双发后果：用户体验降级（看到两条提示），不影响功能正确性
```

### 2. 完成判定
```
函数：content === '[JINGWEI_DONE]'（严格逐字匹配）

匹配规则：
  - 完全相等 → 完成
  - 任何差异（空格、换行、大小写、额外字符）→ 不完成

判定对象：
  - 只检查 lastPromptMessageId 之后的首条 assistant 消息
  - 用户消息/工具消息/系统消息 不参与判定
```

### 3. 锚点写入
```
触发发送 → sendCheckPrompt() → 获得 messageId 
  → 立即写入 state.lastPromptMessageId 
  → 进入 waiting 阶段
  → reconcile 使用该锚点判定

保证：
  - waiting 阶段必须有 lastPromptMessageId
  - 无锚点 → 立即进入 anchor_lost error
```

## 测试要点

| 场景 | 预期 |
|------|------|
| Owner竞争 | claim竞争 + isOwner确认，双发概率极低 |
| 发送前二次确认 | isOwner()返回false → 不发送 |
| 完成判定严格 | `"[JINGWEI_DONE]"` → 完成；`"[JINGWEI_DONE] "` → 不完成 |
| 锚点丢失 | 恢复时找不到lastPromptMessageId → anchor_lost |
| 超时降级 | waiting 5分钟 → reply_timeout → idle |
| 重试计数 | session-local，A会话失败不影响B会话 |
